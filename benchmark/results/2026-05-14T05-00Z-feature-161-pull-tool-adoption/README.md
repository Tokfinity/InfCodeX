# Repointel Pull-Tool Adoption — FEATURE_161/162/163 decision snapshot

**Date**: 2026-05-14
**Eval design**: [tests/repointel-tool-adoption.eval.ts](../../../tests/repointel-tool-adoption.eval.ts)
**Shipped in**: v0.7.41 — commits `c7df89be` (F161 worker prompt teach + F162 confidence aggregation + F163 reverse guidance), `b565783c` (M1/M2 orphan validation + doc), `87f98a2c` (B0 + B0.5 OSS confidence honesty), KodaX-private `2c1fb8a` (daemon confidence tier-aware).
**Why version-tracked** (per `benchmark/results/.gitignore` policy): this snapshot is the decision evidence for shipping F7 (Worker prompt teaches the 8 repointel pull-tools) and for **rejecting** L2 preturn-strategy optimization. Subsequent work should compare against this baseline.

## Background

User reported "几个版本没见到 repointel 工具被调用" — 0 calls in recent native sessions across the 8 pull-tools (`repo_overview` / `changed_scope` / `changed_diff` / `changed_diff_bundle` / `module_context` / `symbol_context` / `process_context` / `impact_estimate`). Root cause investigation led to a multi-layer hypothesis:

- **L1**: Worker prompt didn't list the 8 tools post-FEATURE_114 AMA Harness V2 cutover → fix via F7 (worker-role-prompt.ts REPO INTELLIGENCE TOOLS section)
- **L2**: preturn injection might cause "enough info" illusion suppressing pull-tool calls
- **L3** (OSS-only): symbol confidence binary {0.52, 0.64} with no tier differentiation
- **L4** (OSS-only): `routingSignals.lowConfidence: true` hardcoded

## Artifacts

### `eval/` — F7 Layer 2 single-turn LLM probe results

Generated by `tests/repointel-tool-adoption.eval.ts`, dumped via `KODAX_EVAL_DUMP_DIR` to `%LOCALAPPDATA%/Temp/kodax-eval-dumps/repointel-tool-adoption/` then copied here.

- `_suite-summary.json` — per-alias headline numbers (baseline / B_with_f7 / C_old_reverse / D_new_tools_first), F7 lift percentage points, pre-registered verdict
- `module_understanding.json` — case 1 (5 prompts about a module's surface area)
- `process_trace.json` — case 2 (trace a request's execution path)
- `rename_impact.json` — case 3 (find call sites + tests for a rename)
- `review_changes.json` — case 4 (review changed-scope blast radius)
- `symbol_usage_trace.json` — case 5 (find where a symbol is consumed)

**Eval design**: 4 variants × 5 cases × 6 aliases × 3 runs = 360 LLM calls. The 5 alias subset shipped (`zhipu/glm51`, `kimi`, `mmx/m27`, `ark/glm51`, `ds/v4pro`, `ds/v4flash`) covers strong + weak adopters. Variants:
- A_baseline — pre-F7 Worker prompt
- B_with_f7 — F7-added REPO INTELLIGENCE TOOLS section
- C_old_reverse — F7 + the pre-F2 reverse-guidance wording (control for F2)
- D_new_tools_first — F7 + listing pull-tools before read/grep dispatch (alternative ordering)

**Pre-registered decision matrix** (in `_suite-summary.json`):
| Verdict | Criterion | Result |
|---|---|---|
| `BASELINE_SUFFICIENT` | ≥4 of 6 aliases hit ≥80% A_baseline | 2/6 → not met |
| `F7_USEFUL_FOR_WEAK` | ≥2 aliases lifted from <80% A to ≥80% B AND ≤1 alias still <80% B | **4/6 lifted, 0 stuck → MET** |
| `F7_INSUFFICIENT` | ≥3 aliases still <80% with B_with_f7 | not met |

**Outcome**: `F7_USEFUL_FOR_WEAK`. Weak-alias lifts: `kimi` 60→100% (+40pp), `mmx/m27` 33→80% (+47pp), `ds/v4pro` 47→93% (+47pp), `ds/v4flash` 40→80% (+40pp). Strong aliases (`zhipu/glm51` 93→100%, `ark/glm51` 87→100%) confirm no regression.

### `layer1-preturn-bytes/` — Layer 1 measurement of preturn injection size (native path)

Generated by `measure.mjs` calling the real `premium-native` daemon at `http://127.0.0.1:47891` with 5 real KodaX/KodaX-private scenarios.

- `measure.mjs` — measurement script. Calls daemon RPC `preturn` command; faithfully ports `renderModuleContext` / `renderImpactEstimate` from `query-fallback.ts:1699-1776`
- `report.json` — measurement output (5 scenarios, per-section byte counts)

**Key numbers** (UTF-8 bytes):
| Scenario | conf M/I | lowConf | routing JSON | module sec | impact sec | repoCtx | total inj |
|---|---|---|---|---|---|---|---|
| KodaX root fresh | 0.82/0.82 | no | 525 | 1160 | 2268 | 3448 | **6880** |
| KodaX root cached | 0.82/0.82 | no | 525 | 1160 | 2268 | 3448 | **6880** |
| KodaX/packages/coding | 0.76/0.76 | no | 566 | 1539 | 1260 | 3448 | **6251** |
| KodaX/coding/src/repo-intelligence | 0.76/0.76 | no | 566 | 1539 | 1260 | 3448 | **6251** |
| KodaX-private/repointel-core | 0.82/0.82 | no | 534 | 880 | 1340 | 2340 | **4564** |

**Outcomes from this measurement**:

1. **Preturn is 4.6-6.9KB total in native, not 35-90KB** (the larger figure conflated preturn with read/grep `tool_result` loops). Decision: L2 preturn strategy optimization (P3 in GLM's plan) **rejected** — would save ~6KB but force redundant RPC for content already in capsule, net ROI ≤ 0.

2. **Native `lowConfidence` is reliably FALSE** (0.76-0.82 ≥ 0.72 threshold across all 5 scenarios). Implication: the fallbackGuidance branch at `middleware/repo-intelligence.ts:198-204` essentially never fires in native — F2 (reverse guidance) and B0.5 are correctness fixes for the OSS path only.

3. **F7 (Worker prompt) is THE production lever**. F2/F162/B0/B0.5 are correctness-focused fixes on OSS / dormant-in-native code paths.
