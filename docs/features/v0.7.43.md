| 调研项 | 真实实现 | 我的旧 RFC 假设 |

### opencode / pi-mono 对照

**opencode 无 memory 机制** — `instruction.ts` 仅加载 `AGENTS.md` / `CLAUDE.md` / `CONTEXT.md` 静态 instruction；`MemoryState` 是 RAM session entries 的内存状态，不是跨 session memory。

**pi-mono 无 memory 机制** — `system-prompt.ts` 仅 contextFiles + skills，无 memory 注入；`session-manager.ts` 仅 session reload state（非跨 session）。

两者都把跨 session 知识托付给 AGENTS.md / CLAUDE.md 静态 instruction —— **这是用户主动维护的规则**，不是 LLM 自动积累的事实。

### KodaX 当前覆盖盘点

| 机制 | 路径 | 覆盖 | 不覆盖 |
|---|---|---|---|
| 全局用户规则 | `~/.kodax/AGENTS.md` | 用户级永久规则 | 动态反馈 / project state |
| 项目规则 | `<repo>/AGENTS.md` / `CLAUDE.md` / `<repo>/.kodax/AGENTS.md` | 项目永久规范 / ADR | 用户反馈 / 偏好动态演化 |
| KodaX 全局配置 | `~/.kodax/config.json` | provider / compaction 参数 | 用户行为偏好 |
| Session 持久化 | `~/.kodax/sessions/*.jsonl` | 完整对话历史 | 跨 session key insight 提取 |
| Session Lineage | `packages/session-lineage/` | session 内分支 / label / compaction | 跨 session 连续性 |
| Repointel-Protocol | `packages/repointel-protocol/` | session 启动 repo 智能上下文 | 用户偏好 / 历史反馈 |

**真正的 gap**：KodaX 没有"LLM-owned、per-project、动态可写、session 启动自动注入"的文件系统 memory 层。**用户必须手动维护 AGENTS.md 才能让 agent 跨 session 记住反馈**——这是 FEATURE_124 解决的 gap。

### 真实必要的 memory 场景（去掉已被现有机制覆盖的）

| 场景 | memory 必要性 | 现有覆盖 |
|---|---|---|
| LLM 接收"测试不要 mock 数据库"反馈后自动持久化 | **必要** | 用户得手动写 AGENTS.md（高摩擦）|
| 用户身份 / 角色 / 偏好（影响回答风格） | **必要** | 完全未覆盖 |
| 时效性强 project 状态（sprint / incident / 决策动机） | **必要** | git log + branch name 部分覆盖；动机不在 git |
| 外部资源指针（Grafana / Linear / Slack URL） | **必要** | CLAUDE.md 可放但要手动 |
| "上次单 PR 重构策略效果好，继续用" | **必要** | 完全未覆盖 |
| "merge freeze 从 2026-05-10 开始" | **必要**（时效性强）| git 不表达 |
| 偏好用 deepseek 写测试 | 不必要 | config.json 覆盖 |
| 项目代码约定 / 架构决策 | 不必要 | AGENTS.md 覆盖 |

## FEATURE_124: Memory System Alignment — 4-Type Taxonomy + Per-Project Isolation + Zero-Custom-Tool Design

**Status**: Planned
**Priority**: Medium
**Category**: Enhancement / Persistence

### 设计

#### Step 1：Per-project 隔离的存储路径

```
~/.kodax/projects/<sanitized-git-root>/memory/
  ├── MEMORY.md                    # 索引（≤200 行 / 25KB）
  ├── user_role.md
  ├── feedback_no_mock_db.md
  ├── project_q2_compliance.md
  └── reference_grafana_oncall.md
```

**`<sanitized-git-root>` 计算**：
```ts
// packages/agent/src/memory/paths.ts
export function resolveMemoryRoot(cwd: string): string {
  const remoteUrl = tryGitRemote(cwd);  // git config --get remote.origin.url
  const key = remoteUrl
    ? sanitize(remoteUrl)        // e.g., "github.com-icetomoyo-KodaX"
    : `local-${hashCwd(cwd)}`;   // fallback for repos without remote
  return path.join(os.homedir(), '.kodax', 'projects', key, 'memory');
}

function sanitize(s: string): string {
  return s.replace(/^https?:\/\//, '')
          .replace(/^git@/, '')
          .replace(/[:@/]/g, '-')
          .replace(/\.git$/, '');
}
```

**与 Claude Code 一致的路径策略**——同一 repo 跨设备路径稳定（key 来自 git remote URL）；无 git remote fallback 到 cwd hash。

#### Step 2：4-type taxonomy（YAML frontmatter 强制 + 降级宽容）

```ts
// packages/agent/src/memory/types.ts
export type KodaXMemoryType = 'user' | 'feedback' | 'project' | 'reference';

export interface KodaXMemoryFrontmatter {
  name: string;        // human-readable short name
  description: string; // one-line search-relevance hint
  type: KodaXMemoryType | undefined;  // undefined = unknown → 不 break
}

export function parseMemoryType(raw: unknown): KodaXMemoryType | undefined {
  if (raw === 'user' || raw === 'feedback' || raw === 'project' || raw === 'reference') {
    return raw;
  }
  return undefined;  // 降级宽容；旧文件 / 未知 type 仍 readable
}
```

**关键：降级宽容**。Frontmatter 解析错误 → log warning，文件仍 readable。Unknown type → undefined（仍可读，但失去 type 索引能力）。**绝不抛错 break session 启动**。

文件格式：
```markdown
---
name: No mock DB in tests
description: Integration tests must hit real DB (mock divergence Q1 incident)
type: feedback
---

Body content here. For feedback type, structure as:
- Rule: Integration tests must hit real DB
- **Why:** Q1 incident — mock-prod divergence masked broken migration
- **How to apply:** When user requests adding tests, never propose Jest mocks for DB layer
```

#### Step 3：MEMORY.md 索引（启动同步注入）

```markdown
- [User role](user_role.md) — Senior backend engineer, Go/PostgreSQL focus
- [No mock DB in tests](feedback_no_mock_db.md) — Mock/prod divergence Q1
- [Q2 compliance migration](project_q2_compliance.md) — Auth rewrite by 2026-06-30
- [Grafana oncall dashboard](reference_grafana_oncall.md) — Check before request handling changes
```

格式纪律：每行一个 entry，`- [Title](filename.md) — one-line hook`，hook ≤150 字符。

**索引上限 200 行 / 25KB**：超过则截断 + 提示 LLM 用 `Glob ~/.kodax/projects/<root>/memory/*.md` 主动列出。

#### Step 4：Session 启动同步注入

```ts
// packages/coding/src/agent-runtime/system-prompt-builder.ts
function buildMemorySection(cwd: string): string {
  const memoryDir = resolveMemoryRoot(cwd);
  const memoryMd = path.join(memoryDir, 'MEMORY.md');
  if (!fs.existsSync(memoryMd)) return '';

  let content = fs.readFileSync(memoryMd, 'utf-8');
  if (content.length > 25_000) {
    content = content.slice(0, 25_000) +
      '\n\n[truncated; use `Glob ~/.kodax/projects/<root>/memory/*.md` to list all memory files]';
  }
  return [
    '=== Persistent memory (cross-session) ===',
    `Memory directory: ${memoryDir}`,
    '',
    content,
    '',
    '[See memory rules section below for when to write / read]',
  ].join('\n');
}
```

注入位置：Worker base system prompt 的 stable 部分（在 cache_control boundary 之前，让 cache 命中）。

#### Step 5：LLM 操作 — 零专属工具

**核心设计判断**：LLM 用**既有** Write / Read / Grep / Edit / Glob 工具直接操作 memory 目录。

| 操作 | 工具 | 用法 |
|---|---|---|
| 保存新 memory | `Write` | `Write(path="~/.kodax/projects/<root>/memory/feedback_no_mock_db.md", content="<frontmatter+body>")` 然后 `Edit MEMORY.md` 加索引行 |
| 读取 memory | `Read` | `Read(path="~/.kodax/projects/<root>/memory/feedback_no_mock_db.md")` |
| 搜索 memory | `Grep` | `Grep(pattern="mock", path="~/.kodax/projects/<root>/memory/")` |
| 更新 memory | `Edit` | 既有 edit 工具 |
| 删除 memory | `Bash` | `rm -- "<path>"` 然后 `Edit MEMORY.md` 移除索引行 |
| 列出 memory | `Glob` | `Glob("~/.kodax/projects/<root>/memory/*.md")` 或 read MEMORY.md |

**优势**：
- 极简哲学贯彻 — `NEVER add abstractions until 3+ concrete use cases`
- LLM 已熟悉 Write / Read / Grep / Edit / Glob 五件套，零学习成本
- 用户在 transcript 看到的 tool call 是普通 Write/Read（带特殊 badge），不是黑盒 save_memory
- 升级 / 兼容简单——memory format 改了不影响工具

**与 Claude Code 一致**——调研实证：Claude Code `src/memdir/` 不暴露专属工具，靠 `isAutoManagedMemoryFile()` path detection 在 UI 层加 badge。

#### Step 6：Path detection helper + REPL badge

```ts
// packages/agent/src/memory/paths.ts
export function isAutoManagedMemoryFile(filePath: string): boolean {
  const normalized = path.resolve(filePath);
  const memoryRootPattern = path.join(os.homedir(), '.kodax', 'projects');
  return normalized.startsWith(memoryRootPattern) &&
         normalized.includes('/memory/') &&
         normalized.endsWith('.md');
}
```

REPL 在 transcript 显示 LLM Write 操作时检测 path：
```
✔ Write ~/.kodax/projects/github.com-icetomoyo-KodaX/memory/feedback_no_mock_db.md  [memory:feedback]
  +12 lines
```

`[memory:feedback]` badge 让用户清楚知道 LLM 正在写持久化记忆，区别于普通文件 write。

#### Step 7：`/memory` slash command（用户编辑入口）

```
/memory                     # 列出当前 project 的 memory 文件，let user pick
/memory edit <filename>     # 直接打开 $EDITOR 编辑指定 file
/memory list                # 显示当前 project memory 列表
```

底层调用：
```ts
// packages/repl/src/commands/memory.ts
async function memoryEdit(filename: string, ctx) {
  const memoryDir = resolveMemoryRoot(ctx.cwd);
  const filePath = path.join(memoryDir, filename);
  const editor = process.env.EDITOR ?? 'vi';
  await spawn(editor, [filePath], { stdio: 'inherit' });
  // 编辑后下个 turn system prompt 会重新构造，反映改动
}
```

**关键设计判断**：`/memory` 不是给 LLM 的，是给**用户**的——让用户手动 review / 修正 LLM 写的 memory。LLM 写错了用户能介入。

#### Step 8：Memory rules system prompt（边界声明）

加入 Worker base system prompt：

```
=== Memory rules ===

Your persistent memory at ~/.kodax/projects/<root>/memory/ is YOUR auto-managed
cross-session knowledge layer. Use existing Write/Read/Grep/Edit/Glob tools
to operate on it. No special memory tool exists.

WRITE memory when learning:
- user — user's role / preference / responsibility / knowledge
- feedback — user corrects you ("don't do X") OR confirms a non-obvious
  approach worked ("yes exactly, keep doing that")
- project — current sprint / incident / decision motivation
  (convert relative dates to absolute, e.g., "Thursday" → "2026-05-08")
- reference — pointers to external systems (Linear / Slack / Grafana / dashboard URLs)

DO NOT WRITE memory for:
- Code conventions / architecture decisions / test specs
  → those go to <repo>/CLAUDE.md or <repo>/AGENTS.md (user-managed)
- Git history / who-changed-what (git log/blame is authoritative)
- Debugging fix recipes (commit message is the record)
- Ephemeral / in-progress task state
- Anything already documented in CLAUDE.md / AGENTS.md (avoid duplication)

Two-step save procedure:
1. Write the memory file with YAML frontmatter:
   ---
   name: <short title>
   description: <one-line search hint>
   type: user | feedback | project | reference
   ---
   <body markdown>
2. Append a one-line entry to MEMORY.md:
   - [<title>](<filename>.md) — <hook>

Verification before recommending from memory:
- File path mentioned in memory? → check it still exists.
- Function name / flag mentioned? → grep for it.
- Memory snapshot summarizes repo state? → trust git log over old snapshots.
- Stale memory found → update or delete via Edit / Bash rm.
```

边界声明**关键**——明确告诉 LLM "Code conventions / architecture decisions are in AGENTS.md, not memory"——这条 Claude Code 花了专项 eval 才稳定的指令文本，KodaX 直接复用其逻辑。

#### Step 9：v1 不做 per-turn relevance retrieval

Claude Code 的 `findRelevantMemories.ts` 用 Sonnet side-query 在每个 turn 选 ≤5 个 topic 文件按相关性召回。**KodaX v1 不做**：

理由：
- side-query 成本（每 turn 多一次 LLM call ~500 tokens）
- 复杂度（要 implement scoring + re-rank）
- 启动期 memory 数量小（< 20 条），全量索引注入足够

**触发升级条件**：当用户的 memory 文件数 > 50 / 用户反馈"启动 prompt 太长"时再补 relevance retrieval（可作为 v2 增量）。

### 验收标准

1. **Per-project 隔离**：在 KodaX repo 写的 memory 不出现在其他 repo（不同 sanitized git root → 不同目录）
2. **Frontmatter 降级宽容**：缺 frontmatter / 损坏 YAML / unknown type 的 file 仍 readable，仅 log warning
3. **Session 启动注入**：MEMORY.md 内容在 Worker system prompt 中可见；超过 25KB 截断 + 提示 Glob
4. **LLM 自主使用既有工具操作 memory**：
   - 用户给反馈 → LLM 主动 `Write` 到 memory 目录
   - LLM 不调用任何"专属 memory 工具"（因为本来就没有这种工具）
   - LLM 用 `Read` / `Grep` 读取 memory 时正常工作
5. **Path detection badge**：用户在 transcript 看到 LLM 写 memory 时显示 `[memory:feedback]` 等 badge
6. **`/memory` 命令**：列出当前 project memory；编辑后下一 turn system prompt 反映改动
7. **跨 session 持久化**：session1 LLM 写的 memory 在 session2 启动时可见
8. **边界遵守（prompt eval）**：8 alias × 4 写触发场景 + 4 反例场景，**主动写正确率 ≥80% / 反例不写正确率 ≥80%**
9. **跨 family 验证**：4 family LLM（GLM/Kimi/Claude/GPT）memory 写 / 读行为 max-min spread ≤ 15pp
10. **Stale 检测**：LLM 在使用 memory 前 verify（grep / read）— prompt eval 验证此行为
11. **无回归**：所有既有 prompt eval / runner / tool / dispatch 路径全绿

### 非目标

- **不** 引入 5 个 / 任何专属 memory 工具（save_memory / read_memory / etc.）—— LLM 用既有 Write/Read/Grep/Edit/Glob 操作
- **不** 替代 CLAUDE.md / AGENTS.md（独立角色 — agent auto-managed vs user-managed）
- **不** 引入 memory 加密 / 多用户 ACL（v1 单 user，与 KodaX threat model 一致）
- **不** 引入 memory sync 跨设备（用户自决用 dotfiles repo 同步 `~/.kodax/projects/<root>/memory/`）
- **不** 引入 memory expiration / GC（LLM 主动 Bash rm 即可；用户也可手动删）
- **不** 实现 memory 全文搜索 / vector search（Glob + Grep 足够）
- **不** v1 实现 per-turn relevance retrieval（Sonnet side-query；等 memory 数 > 50 再补）
- **不** 把 memory 暴露为对 user 透明的"自动持久化层"（用户能在 transcript 看到 [memory:type] badge，知道 LLM 在写 memory）

### 与 AGENTS.md / CLAUDE.md 的边界

| 路径 | 谁维护 | 内容 | 何时写 |
|---|---|---|---|
| `~/.kodax/AGENTS.md` | **用户** | 跨项目用户级永久规则 | 用户主动编辑 |
| `<repo>/AGENTS.md` / `CLAUDE.md` | **用户** | 项目级永久规范 / ADR / 架构决策 | 用户主动编辑（PR review 时改）|
| `~/.kodax/projects/<root>/memory/*.md` | **LLM 自动维护** | 跨 session 动态反馈 / 偏好 / project state / external pointer | LLM 在对话中学到时主动 Write |

**用户绝不应该编辑 AGENTS.md 来记录 "测试不要 mock 数据库" 这种反馈**——那是 LLM 应该 Write 到 memory 的事。AGENTS.md 是"项目永远遵循的规则"，memory 是"LLM 学到的、可能随时间演变的事实"。
