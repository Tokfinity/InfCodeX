# v0.7.40 Feature Designs

> 中文标题：`v0.7.40 Feature 设计`
>
> Version: `v0.7.40`
>
> Status: Planned (not yet released)
>
> Theme: **Child Agent Scratchpad** — child 把大块结果（如完整文件内容、大量 grep 结果、长 audit report）写入 scratchpad；Worker 按需 read，避免大输出直接灌进 Worker tool result 撑爆 context。

---

## 总览

v0.7.36 / v0.7.39 之后，Worker 派 read-only child 做研究的频率会大幅上升（Pattern B 异步 + FEATURE_155 idle-yield 回灌 + send_message steering）。但当前 child 完成时**整个结果作为字符串塞进合成 user message 的 `<task-completed task_id="…">…</task-completed>` payload 回灌进 Worker 下一轮 context**（v0.7.39 FEATURE_155 删 `await_child_task` 工具后 child 结果通过 message queue 回灌，不再走 tool result）——如果 child audit 一个大模块产出 30KB 报告，Worker 下一轮 context 立刻被吃 ~7.5k tokens。

业界对照：

- **Claude Code Coordinator** 用 `synthetic_output` 工具让 worker 把大输出写入临时缓冲，coordinator 决定是否 read
- **OpenCode** 的 task tool 输出全 inline，无缓冲机制（KodaX 当前同此）
- **pi-mono** 用 EventStream 流式但仍 inline

KodaX 选 Claude Code 风格——child 自决是否走 scratchpad，Worker 按需 read。

## FEATURE_121: Child Agent Scratchpad — Decoupled Large Output Channel

**Status**: Planned
**Priority**: Medium
**Category**: Enhancement / UX

### 背景

#### 当前 child 输出路径

[`packages/coding/src/child-executor.ts`](../../packages/coding/src/child-executor.ts) child 完成时返 `KodaXChildExecutionResult`，`finalText` 字段经 `dispatch-child-tasks.ts` 的 IIFE `enqueueChildTaskNotification` 塞进合成 user message 的 `<task-completed task_id="…">…</task-completed>` payload，由 runner-driven 外层 loop 在 Worker 下一轮回灌（v0.7.39 FEATURE_155 idle-yield 路径）。

**问题场景**：
- Worker 派 child 做 "audit 整个 packages/coding/src/task-engine 目录" → child 返 30KB 报告 → `<task-completed>` payload = 30KB → Worker 下一轮 context 一次吃 ~7.5k tokens
- Worker 派 3 个并行 read-only child 做 "extract types from each file" → 3 × 15KB = ~11k tokens 一次进 Worker 下一轮

**Phase 0.7 实测**：Claude Code Coordinator 在 6 月数据中 73% 的 worker invocation 用了 synthetic_output 缓冲（coordinator 只 read 关键摘要，详情按需 read）。

#### KodaX 的简化版本

不引入 synthetic_output 这种复杂机制。直接让 child 写一个**短摘要 + 可选 scratchpad path**：

```
Child 完成时返：
  finalText: "Audit complete. Found 4 issues in 3 files. Summary: [...3 行...]
              Full report at: kodax-scratch://child-{task_id}-report.md"
```

Worker 看到 `kodax-scratch://...` URI 时按需调 `read_scratchpad(uri)` 工具拿全文。

### 设计

#### Step 1：Scratchpad storage（in-memory + 可选 disk fallback）

```ts
// packages/agent/src/scratchpad/store.ts
class KodaXScratchpadStore {
  private store: Map<string, string> = new Map();
  private readonly maxSizePerEntry = 256_000;  // 64k tokens worth

  write(uri: string, content: string): void {
    if (content.length > this.maxSizePerEntry) {
      // truncate with notice
      content = content.slice(0, this.maxSizePerEntry) + '\n\n[truncated: scratchpad max size 256KB]';
    }
    this.store.set(uri, content);
  }

  read(uri: string): string | null {
    return this.store.get(uri) ?? null;
  }

  cleanup(parentTaskId: string): void {
    for (const key of this.store.keys()) {
      if (key.includes(`child-${parentTaskId}`)) this.store.delete(key);
    }
  }
}
```

**关键**：
- 不持久化到磁盘（v1 in-memory 即可，重启丢失符合 KodaX session-scoped 一致性）
- 64k tokens 单条上限——超过强制截断（防滥用）
- parent task 完成时 cleanup（避免长 session 累积）

#### Step 2：`write_scratchpad(uri, content)` 工具（child 用）

```ts
const writeScratchpadSchema = {
  uri: z.string().regex(/^kodax-scratch:\/\/[a-z0-9-_]+$/)
    .describe('Scratchpad URI. Recommended format: kodax-scratch://child-{your-task-id}-{kind}.{ext}'),
  content: z.string().describe('Content to write. Max 256KB.'),
};

async function toolWriteScratchpad(input, ctx): Promise<string> {
  ctx.scratchpad.write(input.uri, input.content);
  return `Wrote ${input.content.length} bytes to ${input.uri}`;
}
```

#### Step 3：`read_scratchpad(uri)` 工具（Worker / 其他 child 用）

```ts
const readScratchpadSchema = {
  uri: z.string().describe('Scratchpad URI written by some child agent'),
};

async function toolReadScratchpad(input, ctx): Promise<string> {
  const content = ctx.scratchpad.read(input.uri);
  if (content === null) return `[Tool Error] Scratchpad URI not found: ${input.uri}`;
  return content;
}
```

#### Step 4：Child role-prompt 引导

```
Scratchpad protocol (when your output is large):
- If your final report exceeds ~3000 chars or contains many file dumps,
  use write_scratchpad(uri, content) to store the full report.
- In your final emit, return a SHORT summary (2-5 lines) + the URI:
    "Audit found 4 issues in 3 files: [brief list].
     Full report: kodax-scratch://child-{your-id}-report.md"
- Worker will read the scratchpad if it needs details.

When NOT to use scratchpad:
- Short factual answers (<1000 chars) → just return inline
- Code snippets needed verbatim → inline (Worker may copy them)
- Single-line lookup result → inline
```

#### Step 5：Worker role-prompt 引导

```
When reading child results:
- If child returned a kodax-scratch:// URI, decide whether you need the full
  report based on the summary. Don't always read; trust the summary if it
  answers your question.
- read_scratchpad fetches the full content.
- Multiple children can write to scratchpad; you can read across all of them.
```

### 验收标准

1. **child 写 / Worker 读 round-trip**：child 写 30KB 报告到 scratchpad，返 `kodax-scratch://...` URI；Worker 调 read_scratchpad 拿到完整内容
2. **截断生效**：child 试图写 300KB → 截断到 256KB + 注释 `[truncated: scratchpad max size 256KB]`
3. **未知 URI 报错**：read_scratchpad 不存在的 URI 返 `[Tool Error] Scratchpad URI not found`
4. **cleanup 工作**：parent task 完成后，相关 scratchpad URI 不再可读
5. **child 自决使用 scratchpad**：FEATURE_104 prompt eval 验证 child 在 "audit 大模块" 类任务**主动**使用 scratchpad（而不是把 30KB 全 inline 返）；short lookup 任务**不**使用 scratchpad
6. **Worker 自决是否 read**：Worker 看到摘要够答用户问题时**不** read 详情；摘要不够时主动 read
7. **跨 child 共享**：child A 写 scratchpad，child B（同 parent task）read 该 URI 成功（不限制 reader 必须是 Worker）
8. **跨 family 验证**：4 family LLM scratchpad 使用决策正确率 max-min spread ≤ 15pp
9. **无回归**：既有 child finalText 路径全绿；FEATURE_119 / FEATURE_120 测试不受影响

### 非目标

- **不** 持久化 scratchpad 到磁盘（重启丢失，与 message queue / TodoStore 一致）
- **不** 引入复杂的 namespace / ACL（v1 全 session 共享，足够）
- **不** 强制 child 用 scratchpad（child 自决；short answer 仍 inline）
- **不** 给 user 暴露 scratchpad UI（仅 agent 间用）
- **不** 跨 task / 跨 session 持久化（每个 task 独立空间）
- **不** 实现 streaming write/read（v1 是 atomic write + atomic read）
- **不** 引入 versioning（write 同 URI 覆盖；child 自决用不同 URI 区分版本）

### 与其他 Feature 的关系

- **依赖 FEATURE_119（v0.7.36）**：Pattern B child registry 是 cleanup 的触发点
- **协同 FEATURE_120（v0.7.39）**：scratchpad 用于大输出；send_message 用于短 steering 指令——两者不重叠
- **辅助 FEATURE_122（v0.7.41）**：PM thinking framework prompt 引导 Worker 更系统地使用 child summary + scratchpad
