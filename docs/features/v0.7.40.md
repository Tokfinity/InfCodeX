## 总览

### v0.7.40 范围调整说明（vs 原稿）

原 v0.7.40 设计稿（写于 v0.7.36 / v0.7.39 之前）规划 FEATURE_121 为"Child Agent Scratchpad — 新建 in-memory store + `write_scratchpad` / `read_scratchpad` 两个新工具 + `@kodax/agent/scratchpad/` 新包目录"。v0.7.39 实施后事实核查发现：

1. **claudecode 真实做法不是"scratchpad"** — claudecode `SyntheticOutputTool`（实名 `StructuredOutput`）是 `--print --json-schema` 非交互模式的 output contract，**不是** 大输出缓冲机制（[c:/Works/claudecode/src/tools/SyntheticOutputTool/SyntheticOutputTool.ts](file:///c:/Works/claudecode/src/tools/SyntheticOutputTool/SyntheticOutputTool.ts)）。claudecode 处理大 tool_result 的真实机制是 framework-level **threshold-based auto-spillover**：单个 tool_result > 50KB chars 自动写到 `<sessionId>/tool-results/<toolUseId>.txt`，content 替换为 preview + path（[c:/Works/claudecode/src/utils/toolResultStorage.ts:189-198](file:///c:/Works/claudecode/src/utils/toolResultStorage.ts)），coordinator 用标准 Read tool 按需读全文。同时 per-message 聚合 200KB cap 防 N×中等输出（[c:/Works/claudecode/src/constants/toolLimits.ts:49](file:///c:/Works/claudecode/src/constants/toolLimits.ts)）。
2. **KodaX 已有等价机制** — [`packages/coding/src/tools/tool-result-policy.ts`](../../packages/coding/src/tools/tool-result-policy.ts) 实装了 `applyToolResultGuardrail(toolName, content, ctx)` 统一入口 + `persistToolOutput` spill-to-file，read / bash / grep / web_search / write / edit 等所有普通工具都走这套（50KB / 32KB / 24KB 按工具分档）。
3. **真正 gap 是 envelope 路径绕开了 policy** — child task 完成路径 [`packages/coding/src/orchestration.ts:1033`](../../packages/coding/src/orchestration.ts) 调 `truncateText(lastText, 1600)` 把 child 输出砍到 1600 chars，再在 [`packages/coding/src/tools/dispatch-child-tasks.ts:256`](../../packages/coding/src/tools/dispatch-child-tasks.ts) `summary.slice(0, 200)` 又砍到 200 chars 进 `<task-completed>` banner。25KB audit 报告 → Worker 拿到 ~200 chars (~50 tokens) → 95%+ 细节丢失。**这是隐性 silent data loss bug**，不是"context bloat"。

v0.7.40 把 FEATURE_121 重定位为**"envelope 接入现有 spillover 体系"的 gap-fix**：删两层硬截断、per-banner 走 guardrail、加 200KB 聚合 cap、复用 Read 工具。零新工具、零新包、零 prompt eval（framework 决策非 LLM 决策）。

FEATURE_134 保持原方向（vision bridge），但实施层重新对齐 claudecode `usePasteHandler.ts` 蓝本 + 关键差异（jimp 替代 sharp、AI 层 vision 序列化已存在所以不需"12-provider adapter 层"、跨平台 keybind 平台差异化）。

## FEATURE_121: Envelope Spillover Gap-Fix — Child Task Summary 接入 Tool Result Policy

**Status**: Planned
**Priority**: Medium-High（修复 silent data loss + 为 FEATURE_122 v0.7.41 PM 框架铺路）
**Category**: Bugfix / Enhancement

### 背景

#### v0.7.39 之后 child task 完成回流的精确节拍

FEATURE_119 v0.7.36 Pattern B + FEATURE_155 v0.7.39 idle-yield 之后，Worker 派 child 的流动路径：

```
Worker turn
  └─ dispatch_child_tasks([{role:'scout', prompt:'audit X'}, ...])
     └─ 同步返回 task_id（child 注册 task-registry，async 跑）
     └─ Worker turn 结束（无更多 tool call）

Runner.run 返回 → runWithIdleYield 接管
  └─ detectIdleYield 判定有 pending child → waitForWakeEvent
     └─ "first-child-wins" race（packages/agent/src/orchestration/idle-yield.ts:286-319）
     └─ 任一 child 完成立即 wake，不等其他

child A 完成 → IIFE 调 enqueueChildTaskNotification
  └─ packages/agent/src/messaging/drain.ts:105-115
  └─ banner = `<task-completed task_id="A">\n${summary}\n</task-completed>`
  └─ MessageQueue.enqueue({priority: 'background'})

wake event 触发 → composeIdleYieldUserMessage（idle-yield.ts:381）
  └─ drainBackgroundQueue 一次性 dequeue 所有 background priority 消息
     └─ MessageQueue.dequeue 无 limit（queue.ts:71）
     └─ 如 B/C 已完成排队，一次 drain 全部 3 条
  └─ fragments.join('\n\n') → 1 条 synthetic user message

外层 splice
  └─ currentInput = [...runResult.messages, syntheticUserMessage]
  └─ 下次 runOnce 启动 Runner.run，envelope 进 Worker context
```

#### 当前 envelope 的双层硬截断 bug

**第一层** — [`packages/coding/src/orchestration.ts:1033`](../../packages/coding/src/orchestration.ts#L1033) `dispatchChildTaskWorker` 完成路径：

```ts
return {
  success: transformedResult.success,
  output: transformedResult.lastText,
  summary: truncateText(
    transformedResult.lastText || transformedResult.signalReason || ...,
  ),
  ...
};
```

`truncateText` 默认 `maxLength = 1600`（[orchestration.ts:191](../../packages/coding/src/orchestration.ts#L191)）。**child 完整输出 lastText 被砍到 1600 chars 才能存进 summary**。

**第二层** — [`packages/coding/src/tools/dispatch-child-tasks.ts:256`](../../packages/coding/src/tools/dispatch-child-tasks.ts) `enqueueChildTaskNotification` 调用前：

```ts
const summary = (workerResult.summary ?? '').slice(0, 200);
enqueueChildTaskNotification({ taskId, summary });
```

**summary 又被砍到 200 chars**。

**净效应**：
- child 产 25KB audit 报告 → orchestration.ts:1033 砍到 1600 chars → dispatch-child-tasks.ts:256 再砍到 200 chars → envelope 里只有 ~200 chars (~50 tokens) → Worker 看到的是 "audit found 4 issues. The first one is..." 这种残缺片段，95%+ 信息丢失
- child 产 50KB types extract → 同样 200 chars 进 envelope → Worker 完全无从决策

#### KodaX 已有的通用 tool_result 溢出机制

[`packages/coding/src/tools/tool-result-policy.ts`](../../packages/coding/src/tools/tool-result-policy.ts) 已实装：

```ts
const TOOL_RESULT_POLICIES: Record<string, ToolResultPolicy> = {
  read:    { maxLines: 2000, maxBytes: 50 * 1024, direction: 'head', spillToFile: true },
  bash:    { maxLines: 600,  maxBytes: 32 * 1024, direction: 'tail', spillToFile: true },
  grep:    { maxLines: 400,  maxBytes: 24 * 1024, direction: 'head', spillToFile: true },
  // 还有 web_search / web_fetch / code_search / semantic_lookup / changed_diff / write / edit 等
};

const DEFAULT_POLICY: ToolResultPolicy = {
  maxLines: 1200, maxBytes: 40 * 1024, direction: 'head', spillToFile: true,
};

export function applyToolResultGuardrail(
  toolName: string,
  content: string,
  ctx: KodaXToolExecutionContext,
): GuardedToolResult;
```

`GuardedToolResult.content` 自动有两态：
- **content ≤ maxBytes**：原文返回
- **content > maxBytes**：截到 maxBytes（按 direction：head 保留前部、tail 保留尾部）+ 末尾追加 `[Tool result truncated. Full output written to: <abs-path>. Use the Read tool to view full output.]`，spill 文件写到 `getAgentConfigPath('tool-results')/<hash>.txt`（[`packages/coding/src/tools/truncate.ts:247`](../../packages/coding/src/tools/truncate.ts) `persistToolOutput`）

#### 关键观察：envelope 是唯一绕开 policy 的路径

| 路径 | 走 policy guardrail？ | 大输出处理 |
|---|---|---|
| Read 工具结果 | ✅ `applyToolResultGuardrail('read', ...)` | 50KB threshold + spill |
| Grep 工具结果 | ✅ | 24KB threshold + spill |
| Bash 工具结果 | ✅ | 32KB threshold + spill |
| Web search 等 | ✅ | 按 policy |
| **child task `<task-completed>` envelope** | ❌ | **粗暴 200 chars 硬截，无 spill** |

这就是 FEATURE_121 要补的 gap。

#### claudecode 对照

[c:/Works/claudecode/src/tools/AgentTool/AgentTool.tsx:229](file:///c:/Works/claudecode/src/tools/AgentTool/AgentTool.tsx)：sub-agent 完成返 tool_result 全量 inline，由通用 `processToolResultBlock` 走 50KB / 200KB 两层 cap：

- 单个 tool_result > 50KB → 自动 persist 落盘 + preview + path（[toolResultStorage.ts:189-198](file:///c:/Works/claudecode/src/utils/toolResultStorage.ts)）
- 一条 user message 内所有 tool_result 聚合 > 200KB → 选最大的几个 persist 直到 ≤ 200KB（[toolLimits.ts:49](file:///c:/Works/claudecode/src/constants/toolLimits.ts)）

KodaX envelope 是 synthetic user message（多 banner join），不是 tool_result block 集合，但聚合膨胀的物理问题等价（一条 user message 总长度过大）。

### 设计

#### Step 1 — `tool-result-policy.ts` 加 `child_task_summary` policy

**位置**：[`packages/coding/src/tools/tool-result-policy.ts`](../../packages/coding/src/tools/tool-result-policy.ts) `TOOL_RESULT_POLICIES` 表

```ts
const TOOL_RESULT_POLICIES: Record<string, ToolResultPolicy> = {
  // ... existing entries ...
  child_task_summary: {
    maxLines: 1500,
    maxBytes: 50 * 1024,    // 50KB，跟 read 对齐
    direction: 'head',      // child 报告关键结论通常在前
    spillToFile: true,
  },
};
```

**理由**：
- 50KB 阈值跟 read 工具对齐——child 输出本质上也是"被 Worker 消费的报告内容"，吃 token 模式相似
- `direction: 'head'` 而非 tail——child role prompt 引导其在报告头部写 executive summary
- `spillToFile: true` 复用 `persistToolOutput` 写到 `getAgentConfigPath('tool-results')/`

#### Step 2 — 删 `orchestration.ts` 两处 `truncateText(lastText, 1600)`

**位置**：[`packages/coding/src/orchestration.ts:1033`](../../packages/coding/src/orchestration.ts#L1033) 和 [`packages/coding/src/orchestration.ts:514`](../../packages/coding/src/orchestration.ts#L514)

```ts
// Before (orchestration.ts:1033):
summary: truncateText(
  transformedResult.lastText || transformedResult.signalReason || ...,

// After:
summary: transformedResult.lastText
      || transformedResult.signalReason
      || (transformedResult.interrupted ? '...' : 'No textual output produced.'),
```

`OrchestrationWorkerResult.summary` 现在承载完整 child 输出（可能很大），由下游 guardrail 处理。

类似改动应用于 [orchestration.ts:514](../../packages/coding/src/orchestration.ts#L514) `normalizeWorkerResult` fallback 路径。

**注意**：`output` 字段保持原样（也是 lastText 全文），summary 字段语义从"短摘要"变为"原始输出，由下游 guardrail 决定 inline / spill"。`truncateText` 函数本身保留（其他调用方还在用，如 `summarizeFailedDependencies`），只删除针对 worker result 的这两处调用。

#### Step 3 — 删 `dispatch-child-tasks.ts:256` 的 `summary.slice(0, 200)`，改调 guardrail

**位置**：[`packages/coding/src/tools/dispatch-child-tasks.ts:256`](../../packages/coding/src/tools/dispatch-child-tasks.ts)

```ts
// Before:
const summary = (workerResult.summary ?? '').slice(0, 200);

// After:
```

`guarded.content` 自动两态：
- ≤ 50KB：原文 → envelope 含完整 child 报告
- \> 50KB：truncated 头部 + spill path → envelope 含 preview + 文件路径

Worker 看到 spill path 时按需调 Read 工具——已有的工具，零新工具。

#### Step 4 — `composeIdleYieldUserMessage` 加 200KB 聚合 envelope cap（callback 注入模式）

**位置**：
- [`packages/agent/src/orchestration/idle-yield.ts:381`](../../packages/agent/src/orchestration/idle-yield.ts) `composeIdleYieldUserMessage` —— 加 callback 参数
- [`packages/agent/src/orchestration/runner-with-idle-yield.ts:202`](../../packages/agent/src/orchestration/runner-with-idle-yield.ts) —— 通过 options 透传
- [`packages/coding/src/tools/envelope-budget.ts`](../../packages/coding/src/tools/) —— 新文件，提供 enforcer 实现（与 `tool-result-policy.ts` 同目录，因为强依赖 `applyToolResultGuardrail`）

**关键场景**：5 个 child 几乎同时完成（dispatch_child_tasks batched 派出），各产 30KB summary（个体均 < 50KB threshold 不触发 per-banner spill），drain 一次性把 5 个 banner 拼成 1 条 envelope = 150KB user message → Worker 单次 LLM call 吃 150KB tokens。

#### 层独立性约束（CRITICAL）

[ADR-021](../ADR.md) 硬约束 `@kodax-ai/agent` **不依赖** `@kodax-ai/coding`：

- `KodaXToolExecutionContext` 定义在 [`packages/coding/src/types.ts:1370`](../../packages/coding/src/types.ts#L1370)（属 `@kodax-ai/coding`）
- [`packages/agent/package.json`](../../packages/agent/package.json) dependencies 仅含 `@kodax-ai/llm` + `@kodax-ai/tracing` + `js-tiktoken`，**无 `@kodax-ai/coding`**
- `applyToolResultGuardrail` 实现也在 `@kodax-ai/coding`

**因此 idle-yield.ts 内不能直接 import `KodaXToolExecutionContext` 或 `applyToolResultGuardrail`**。采用 **callback 注入模式**：agent 层只看 `string[] → string[]` 纯函数 transform，实际 spill 逻辑由 coding 层注入。

#### 实现

**Agent 层（`@kodax-ai/agent`）—— 纯 string transform 接口**：

```ts
// packages/agent/src/orchestration/idle-yield.ts (revised signature)

export type EnvelopeAggregateEnforcer =
  (fragments: readonly string[]) => readonly string[];

export function composeIdleYieldUserMessage<TChildResult>(
  wakeEvent: WakeEvent<TChildResult>,
  drainBackgroundQueue: () => readonly QueuedMessage[],
  enforceAggregate?: EnvelopeAggregateEnforcer,   // ← 可选 callback，无 coding 类型
): KodaXMessage | undefined {
  const fragments: string[] = [];
  // ... existing wake event reasoning fragments ...
  if (wakeEvent.kind !== 'aborted') {
    const drained = drainBackgroundQueue();
    for (const msg of drained) fragments.push(msg.content);
  }
  if (fragments.length === 0) return undefined;

  const enforced = enforceAggregate ? enforceAggregate(fragments) : fragments;
  return {
    role: 'user',
    content: enforced.join('\n\n'),
    _synthetic: true,
  };
}
```

**Coding 层（`@kodax-ai/coding`）—— enforcer 实现**：

```ts
// packages/coding/src/tools/envelope-budget.ts (新文件，~50 行)

import type { EnvelopeAggregateEnforcer } from '@kodax-ai/agent';
import type { KodaXToolExecutionContext } from '../types.js';
import { applyToolResultGuardrail } from '../tools/tool-result-policy.js';

export const ENVELOPE_AGGREGATE_LIMIT_CHARS = 200_000;  // 跟 claudecode MAX_TOOL_RESULTS_PER_MESSAGE_CHARS 对齐（chars，不是 bytes — claudecode contentSize() 用 .length，作 token 粗估）

export function createEnvelopeAggregateBudgetEnforcer(
  ctx: KodaXToolExecutionContext,
): EnvelopeAggregateEnforcer {
  return (fragments) => {
    const total = fragments.reduce((s, f) => s + f.length, 0);
    if (total <= ENVELOPE_AGGREGATE_LIMIT_CHARS) return fragments;

    // 按 size desc 排序，记录原 index
    const indexed = fragments.map((f, i) => ({ idx: i, content: f, size: f.length }));
    indexed.sort((a, b) => b.size - a.size);

    let totalSize = total;
    const result = [...fragments];

    for (const item of indexed) {
      if (totalSize <= ENVELOPE_AGGREGATE_LIMIT_CHARS) break;
      const forced = applyToolResultGuardrail(
        'child_task_summary',
        item.content,
        ctx,
        { forceSpill: true },
      );
      result[item.idx] = forced.content;
      totalSize = totalSize - item.size + forced.content.length;
    }
    return result;
  };
}
```

#### Step 6 — Eval case 设计

**位置**：`tests/child-task-envelope-spillover.eval.ts`（新文件）

Eval 3 case：
1. **child 输出 ≤ 50KB**（典型场景）→ envelope 全 inline → Worker 直接基于完整内容决策，**不**调 Read 工具读 spillover（避免不必要工具调用）
2. **child 输出 > 50KB**（spillover 触发）→ envelope = preview + spillover path → 若 task 是 "audit X 然后告诉我所有 issue"（需要详情），Worker **调用** Read 拿全文；若 task 是 "audit X，告诉我有没有 critical issue"（看 summary 够），Worker **不调** Read
3. **5 个 child 聚合 200KB 触发 cap**：envelope 含部分 preview + spillover paths → Worker 按需选择性 Read

跨 family 验证（4 family）：spread ≤ 15pp（per [feedback_eval_partial_alias_expansion](../../memory/feedback_eval_partial_alias_expansion.md)）。

### Spill-failure data-loss guard（v0.7.40 post-audit fix，2026-05-13）

**Bug**：审计 dispatch→Worker 全路径时发现 [`tool-result-policy.ts`](../../packages/coding/src/tools/tool-result-policy.ts) `applyToolResultGuardrail` 在 `persistToolOutput` 抛错（磁盘满 / EACCES / EROFS / ENOSPC / SELinux 拒绝 / NFS 断线）时悄悄吞错：catch 块设 `outputPath = undefined` 后流程继续，结果是 preview-only banner（前 ~50KB）+ 无 spill marker，剩余 tail bytes **永久丢失**。Worker 收到 banner 说"Tool output truncated"但拿不到 spill path，完全无法恢复，且把 preview 当作全量数据做错误判断。

**修复**：[`tool-result-policy.ts:178-217`](../../packages/coding/src/tools/tool-result-policy.ts#L178-L217) — spill 失败时**不 truncate**，返回完整原 `content` 配 `truncated: false`，让 envelope-budget enforcer 在 banner 拼接时获得第二次 spill 机会；若再失败，全量内容仍以 inline 形式进 LLM context（过 envelope cap 但**可观测**），由 LLM/provider 显式报 token-limit 错。设计契约：**silent data loss > observable over-budget**。

操作员可见性：spill 失败时 `console.warn` 到 stderr（**不** gate 在 `KODAX_DEBUG_TOOL_GUARDRAILS` 后），让磁盘故障立刻浮出。

**测试**：[`tool-result-policy.test.ts`](../../packages/coding/src/tools/tool-result-policy.test.ts) +2 cases —
1. `inlines full content when persistToolOutput fails (data-loss guard)`：把 `KODAX_TOOL_OUTPUT_DIR` 指向一个**文件**（非目录），触发 ENOTDIR；断言 `result.content === largeContent` AND `truncated: false` AND banner 不含 "Tool output truncated" 字样。
2. `inlines full content when forceSpill=true but persistToolOutput fails`：envelope-budget enforcer 路径同等覆盖。

**审计结论**：dispatch→banner→Worker 全路径不再有任何**静默数据丢失**点；任何故障都以 `console.warn` + over-budget inline 的形式显式暴露。

### FEATURE_121 follow-up：LLM 兜底摘要（blob summarizer）

#### 动机

FEATURE_121 v0.7.40 main slice 落地后，spill-failure 路径仍存在一个理论但严重的失败模式：当
`persistToolOutput` 失败（ENOSPC / EACCES / EROFS / SELinux denial）**且**原始内容超大（>100 KB）时，
data-loss guard 会把全量内容内联回 Worker context — 这会冲爆 LLM context window（典型 128K-token 模型
单一 inline 就吃掉 25K tokens），让整个 turn 不可恢复。

之前讨论过两条 fallback：
- **A. 启发式 head/tail 截断** — 用户明确拒绝（"不用 llm直接处理文本一定会影响语义"）。
- **B. 第二次 LLM call 做有损压缩** — 采纳。这是 FEATURE_121 v0.7.40 follow-up 的本质。

设计选择（用户授权）：**Option C 回调注入 + Worker 同款 model**：
- `@kodax/coding` 持 `createBlobSummarizer(provider, model)`（layer 独立 — agent 层不感知 LLM client）
- task-engine init 时把 `summarizeBlob` 回调注入 `KodaXToolExecutionContext`
- 用 Worker 自己的 provider/model（一致性 > 独立 weak-model 决策）

#### 设计

新增 [`packages/coding/src/tools/blob-summarizer.ts`](../../packages/coding/src/tools/blob-summarizer.ts):

```ts
export const LARGE_CONTENT_THRESHOLD_BYTES = 100 * 1024;   // 触发阈值
export const DEFAULT_SUMMARY_MAX_CHARS = 8000;             // 压缩目标上限
export const DEFAULT_SUMMARY_MIN_CHARS = 2000;             // 压缩目标下限
export const DEFAULT_SUMMARY_TIMEOUT_MS = 30_000;          // LLM 调用墙时
export const SUMMARIZER_SYSTEM_PROMPT = '...';             // 暴露给 eval 锁定
export function buildSummarizerUserMessage(content, maxChars): string { ... }

```

触发链路（在 `dispatch-child-tasks.ts` 内统一通过 `applyChildSummaryGuardrailWithSummarizer` helper 调度）：

```
guardrail (持久化失败) → spillFailed: true → inline full content
  └─ if content > 100 KB AND ctx.summarizeBlob exists:
       → 第二次 LLM call (Worker 同款 model) 压缩到 ~2-8 KB
       → 套 "[SPILL FAILED — original ${size} compressed via LLM summarizer]" banner
       → 失败时（empty / abort / provider error）console.warn + fallback to inline full
```

**Layer 独立性保持**：`@kodax/coding` 持 summarizer 工厂；`@kodax/agent` 完全不知道 LLM client 存在；
guardrail (`tool-result-policy.ts`) 也不知道有 LLM 兜底 — 通过 `ctx.summarizeBlob` 回调隐藏。

加 CSI 序列识别：

```ts
const PASTE_START = '\x1b[200~';  // ESC[200~
const PASTE_END   = '\x1b[201~';  // ESC[201~

// parse-keypress tokenizer 加 paste 状态机
function tokenize(input: string): KeypressEvent[] {
  const events: KeypressEvent[] = [];
  let pos = 0;
  let pasteBuffer: string | null = null;

  while (pos < input.length) {
    if (pasteBuffer === null && input.startsWith(PASTE_START, pos)) {
      pasteBuffer = '';
      pos += PASTE_START.length;
      continue;
    }
    if (pasteBuffer !== null) {
      if (input.startsWith(PASTE_END, pos)) {
        events.push({ type: 'paste', content: pasteBuffer });
        pasteBuffer = null;
        pos += PASTE_END.length;
        continue;
      }
      pasteBuffer += input[pos];
      pos++;
      continue;
    }
    // ... 现有 single-char / CSI 处理 ...
  }
  return events;
}
```

**额外**：REPL 启动时发 `ESC[?2004h` 启用 bracketed paste mode（DEC mode 2004），退出时发 `ESC[?2004l` 复位（[`packages/repl/src/interactive`](../../packages/repl/src/interactive) 的 init / shutdown 钩子）。

#### Step 3 — 图片解码 + Resize (jimp)

**位置**：[`packages/repl/src/utils/image-paste.ts`](../../packages/repl/src/utils/) 新增

```ts
import { Jimp } from 'jimp';

const MAX_DIMENSION = 2000;
const TARGET_RAW_SIZE_BYTES = 3.75 * 1024 * 1024;  // 3.75MB（Anthropic 5MB base64 限制反推）

export async function normalizeImage(
  buffer: Buffer,
  hintMime?: string,
): Promise<{ buffer: Buffer; mediaType: string; dimensions: { w: number; h: number } }> {
  const image = await Jimp.read(buffer);
  let { width, height } = image.bitmap;

  // Resize if too large
  if (width > MAX_DIMENSION || height > MAX_DIMENSION) {
    const ratio = MAX_DIMENSION / Math.max(width, height);
    image.resize({ w: Math.round(width * ratio), h: Math.round(height * ratio) });
  }

  // 压缩到 target size（PNG → JPEG quality 阶梯）
  let out = await image.getBuffer('image/png');
  if (out.length <= TARGET_RAW_SIZE_BYTES) {
    return { buffer: out, mediaType: 'image/png', dimensions: image.bitmap };
  }

  // JPEG quality 阶梯 80→60→40
  for (const q of [80, 60, 40]) {
    out = await image.getBuffer('image/jpeg', { quality: q });
    if (out.length <= TARGET_RAW_SIZE_BYTES) {
      return { buffer: out, mediaType: 'image/jpeg', dimensions: image.bitmap };
    }
  }

  throw new ImageResizeError(
    `Image too large after compression (${out.length} bytes > ${TARGET_RAW_SIZE_BYTES}). Try a smaller image.`,
  );
}
```

```ts
import { mkdir, writeFile } from 'node:fs/promises';
import { join } from 'node:path';
import { tmpdir } from 'node:os';
import { randomUUID } from 'node:crypto';

const KODAX_PASTE_DIR = process.env.KODAX_PASTE_TMP_DIR
  ?? join(tmpdir(), 'kodax-paste');

export async function persistImage(
  buffer: Buffer,
  mediaType: string,
): Promise<KodaXImageBlock> {
  await mkdir(KODAX_PASTE_DIR, { recursive: true });
  const ext = mediaType === 'image/jpeg' ? '.jpg' : '.png';
  const filename = `paste-${randomUUID()}${ext}`;
  const fullPath = join(KODAX_PASTE_DIR, filename);
  await writeFile(fullPath, buffer);
  return { type: 'image', path: fullPath, mediaType };
}
```

- `tmpdir()` （OS 临时目录）默认。系统重启清。无需 KodaX 自己 GC。

- 不放 `~/.kodax/`（避免占用用户 home 空间）

#### 5. Source 5 — macOS/Linux Ctrl+V 备份快捷键

- Linux 截图后 Ctrl+V → `readLinuxClipboard` → wl-paste / xclip → persist
- macOS Ctrl+V 备份生效（即使 Cmd+V Source 3 已自动联动，显式 Ctrl+V 仍可触发）

#### 6. 图片正规化

- 4000×3000 PNG → resize 到 2000×1500（按 ratio）
- 单张 10MB JPEG → 压缩到 ≤ 3.75MB（JPEG quality 80→60→40 阶梯）
- 极端大图（压缩到 quality 40 仍 > 3.75MB）→ throw ImageResizeError → REPL 显示错误提示

#### 7. KodaXImageBlock 注入

- 输入 "看一下" + 1 图 → user message content = `[{type:'text', text:'看一下'}, {type:'image', path:'/tmp/kodax-paste/paste-uuid.png', mediaType:'image/png'}]`
- 多图：3 图 + 文本 → content 4 elements 顺序对应
- 空文本 + 1 图 → content = `[{type:'image', ...}]`（无 text block）

#### 8. Provider wire 兼容

- Anthropic：[anthropic.ts:770](../../packages/llm/src/providers/anthropic.ts#L770) 序列化为 `{type:'image', source:{type:'base64', media_type, data}}` ✓
- OpenAI：[openai.ts:904](../../packages/llm/src/providers/openai.ts#L904) 序列化为 `{type:'image_url', image_url:{url:'data:...;base64,...'}}` ✓
- OpenAI-compatible（DeepSeek / Kimi / Zhipu / Qwen / MiMo / MiniMax / Hunyuan）：继承 OpenAI 序列化，自动支持 ✓
- 不支持 vision 的 provider（若有）：序列化时 throw / strip image block，REPL 显示错误（不在 FEATURE_134 scope，由 provider 各自处理）

#### 9. UI 反馈

- 粘贴成功输入框显示 `[Image #N]` 占位
- 删除 `[Image #N]` 字符串 → `pendingImages[N-1]` 自动清除
- 提交后 `pendingImages` 清空，可继续粘贴新图

#### 10. 错误处理

- 图太大（> 3.75MB 压缩后）→ ImageResizeError → REPL 顶部红色 banner
- 剪贴板无图（Alt+V / Cmd+V 空）→ 静默
- 文件路径粘贴但文件不存在 → 当文本粘贴（fallback）
- jimp 解码失败（不支持格式）→ 错误 banner

#### 11. 平台兼容

- Windows 10/11、macOS 13+、Linux（X11 + Wayland）三平台 dogfood 测试通过
- 远程场景（SSH / WSL）：bracketed paste + Source 2 路径粘贴工作；Source 3/4/5 剪贴板可能受限（依终端设置），已知限制写入 [test-guide](../../docs/test-guides/FEATURE_134_v0.7.40_TEST_GUIDE.md)

#### 12. 无回归

- REPL 既有文本输入 / history / 自动完成功能不受 bracketed paste 改造影响
- 现有 keypress 行为（特别是 Ctrl+C / Ctrl+D / 方向键）不受 paste handler 影响
