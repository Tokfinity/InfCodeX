# v0.7.44 Feature Designs

> 中文标题：`v0.7.44 Feature 设计`
>
> Version: `v0.7.44`
>
> Status: Planned (not yet released)
>
> Theme: **Peer-to-Peer SendMessage** — 在 v0.7.39 FEATURE_120（Worker → child SendMessage）之上扩展，让 child agent 之间可以通过 `send_message(to, content)` 直接通信，启用 child-to-child 协作场景；同时落地 `to: '*'` broadcast（v0.7.39 暂禁的 case）。

---

## 总览

v0.7.39 FEATURE_120 实现了 Worker 给在跑 child 续指令——但 send_message 在 child 内部**不可用**（child 工具集没注册）。这意味着：

- child A 派的子 child（grand-child）不能通过 child A 转发消息给同辈 child B
- 多 child 之间无法直接协作（必须经 Worker 中转）
- broadcast `to: '*'` 在 v0.7.39 显式禁用

FEATURE_123 把 send_message **完全 routing-agnostic 化**——不分父子辈，按 agentId 在 message queue 上路由：

- Worker → child（既有，FEATURE_120）
- child → child（peer，新增）
- child → Worker（child 主动通报，新增）
- broadcast `to: '*'` to all running siblings（新增）

这是 v0.7.36 message queue agentId-scoped routing 设计的自然完成态。

---

## FEATURE_123: Peer-to-Peer SendMessage — Child Agent Inter-Communication on Top of FEATURE_120 Routing

**Status**: Planned
**Priority**: Medium
**Category**: Internal / Architecture

### 背景

#### 当前 v0.7.39 后的能力分布

| 路径 | v0.7.39 状态 | v0.7.44 状态 |
|---|---|---|
| Worker → child | ✅ FEATURE_120 send_message | ✅ 不变 |
| child → child（同 Worker 派的兄弟）| ❌ child 无 send_message 工具 | ✅ FEATURE_123 |
| child → Worker | ❌ child 通过 final result 通报 | ✅ FEATURE_123（child 中途主动通报） |
| broadcast `to: '*'` | ❌ FEATURE_120 显式禁用 | ✅ FEATURE_123 |
| grand-child → 父 child | ❌ 不支持 | ✅ FEATURE_123 |
| grand-child → grand-uncle child | ❌ 不支持 | ✅ FEATURE_123 |

#### 为什么 v0.7.44 才做（不在 v0.7.39 一起）

- v0.7.39 ship 后跑生产数据 1-2 月，看 Worker → child 的使用频率和模式
- 若数据显示 Worker 频繁中转 child A 的发现给 child B（典型 fan-out research synthesis pattern），证明 peer-to-peer 有真实价值
- 若数据显示 Worker → child 已足够，FEATURE_123 可推迟

#### Phase 0.7 调研对照

Claude Code Coordinator Mode 的 send_message 是 worker → coordinator 双向；coordinator → worker；worker → worker（peer）三档全开。Claude Code 没特别区分父子辈——纯按 agentId 路由。这是 mature 形态。

KodaX 选择渐进——v0.7.39 先 Worker → child（最常见），v0.7.44 扩展 peer 完全形态。

### 设计

#### Step 1：Child agent 加 send_message 工具

`packages/coding/src/child-executor.ts` 在构造 child tool whitelist 时：

```ts
function buildChildToolWhitelist(childDef: KodaXChildAgentDefinition): string[] {
  const tools = [...]; // 既有
  // FEATURE_123: child can also send_message to peers / Worker
  tools.push('send_message');
  // task_stop NOT given to child (only Worker can stop children)
  return tools;
}
```

#### Step 2：`to: '*'` broadcast 实现

```ts
async function toolSendMessage(input, ctx): Promise<string> {
  const { to, content } = input;
  if (to === '*') {
    // FEATURE_123: broadcast to all running siblings (excluding self)
    const myId = ctx.currentAgentId;  // undefined for Worker; task_id for child
    const targets = [...ctx.childTaskRegistry.keys()].filter(id => id !== myId);
    if (myId !== undefined) targets.push('worker');  // child broadcasting also reaches Worker
    for (const target of targets) {
      ctx.messageQueue.enqueue({
        priority: 'background',  // broadcast 视同 background priority（不抢用户 priority）
        agentId: target,
        mode: 'system-reminder',
        content: `<peer-broadcast from="${myId ?? 'worker'}">\n${content}\n</peer-broadcast>`,
      });
    }
    return `Broadcast sent to ${targets.length} target(s).`;
  }
  if (to === 'worker') {
    // child → Worker
    if (!ctx.parentAgentId) {
      return `[Tool Error] No parent Worker (you are the Worker yourself)`;
    }
    ctx.messageQueue.enqueue({
      priority: 'background',
      agentId: ctx.parentAgentId,
      mode: 'task-notification',
      content: `<child-notification from="${ctx.currentAgentId}">\n${content}\n</child-notification>`,
    });
    return `Notification sent to Worker.`;
  }
  // 既有 FEATURE_120: target by task_id
  if (!ctx.childTaskRegistry.has(to)) {
    return `[Tool Error] Unknown task_id: ${to}`;
  }
  // peer-to-peer routing：child A → child B 不要求 child B 是 child A 派的
  ctx.messageQueue.enqueue({
    priority: 'background',  // peer message 视同 background（child 间协作不抢用户 priority）
    agentId: to,
    mode: 'prompt',
    content: `<peer-message from="${ctx.currentAgentId ?? 'worker'}">\n${content}\n</peer-message>`,
  });
  return `Message sent to ${to}.`;
}
```

#### Step 3：Sleep-gated drain 调整

FEATURE_115 message queue 的 Sleep-gated drain 规则：仅 Sleep tool 跑过才 drain background priority。child 的 `<peer-message>` 是 background——意味着 child 必须显式 Sleep 才会拿到 peer 消息。

**这是设计意图**：child 默认专注做自己的事，不被 peer 打扰；想协作时显式 Sleep（"歇一下看看 peer 进展"）触发 drain。

**Worker 收 peer message 的语义**：Worker 也是 send_message 的合法 target —— child 给 worker 通报。Worker 在 mid-turn drain 中：
- priority='user' 消息（用户输入 + Worker→child 续指令的 echo）→ 每个 tool 边界 drain（既有 FEATURE_115）
- priority='background' 消息（child notification + broadcast）→ 仅 Sleep 后 drain

Worker 在 fan-out 期间默认走 user priority drain；想知道 child 中途通报需主动 Sleep 一次。这与 child 的 Sleep-gated 行为对称。

#### Step 4：Cycle / flood 防护

- **Cycle prevention**：peer-message 内部记录 `seen_by` agentId set；child 不能 forward 给已经 seen 的 agent → return error。`seen_by` 在 message enqueue 时由 send_message 工具自动追加发送方 agentId
- **Flood prevention（分层阈值）**：
  - 单 child 单 turn 内 ≤ **5** 次 send_message 调用
  - 单 Worker 单 turn 内 ≤ **20** 次 send_message 调用（Worker 是协调者，预算更高）
  - 超过返 `[Tool Error] send_message rate limit reached this turn`
  - 阈值依据：peer-to-peer 是协作不是数据 pipeline，5 次/child-turn 已是合理协作量；20 次/worker-turn 覆盖大 fan-out 场景
- **Broadcast 上限**：单次 broadcast targets ≤ 20；超过返 `[Tool Error] broadcast targets exceeded (max 20)`

#### Step 5：Child role-prompt 引导

```
=== Peer Communication (FEATURE_123) ===

You can send messages to peer agents:
- send_message(to=task_id, content="...") — to specific peer child
- send_message(to="worker", content="...") — notify your parent Worker
- send_message(to="*", content="...") — broadcast to all running siblings + Worker

When to use:
- You found something important that affects another peer's task → notify them
- You're stuck and another peer might know → ask them
- You're about to take an action that overlaps with peer's work → coordinate

When NOT to use:
- Don't spam — at most 1-2 peer messages per task
- **Use to: '*' (broadcast) sparingly** — only for facts that genuinely affect
  ≥2 peers (与 claude code `teammatePromptAddendum.ts` 的 "sparingly" 引导对齐，
  防 LLM 滥用 broadcast 造成 message queue 噪音)
- Don't broadcast routine progress (large outputs are handled by envelope spillover; use it through normal task completion, not peer messages)
- Don't try to coordinate complex multi-step tasks via peer messages — that's
  the Worker's job (your task scope was set at dispatch time)

Peer messages arrive as <peer-message from="..."> at your next LLM turn boundary
(Sleep tool required to drain — peer messages are background priority).
```

### 验收标准

1. **child → child peer 路由**：child A send_message(to=child_b_id) → child B 在下个 LLM turn 看到 `<peer-message from=A>` 标签
2. **child → Worker 通报**：child send_message(to='worker') → Worker 在下个 Sleep + LLM call 看到 `<child-notification from=child_id>` 标签
3. **broadcast 正确**：child A send_message(to='*') → 所有兄弟 child + Worker 都收到 `<peer-broadcast from=A>`；child A 自己**不**收到
4. **cycle 防护**：child A → child B → child A 转发循环检测，第二跳报错
5. **flood 防护分层**：单 child 单 turn > 5 次 send_message 报错；单 Worker 单 turn > 20 次 send_message 报错
6. **broadcast 上限**：targets > 20 时报错（运行时 cap，超过返明确 Tool Error）
7. **child 不能 task_stop**：child 调 task_stop 报 `[Tool Error] task_stop only available to Worker`
8. **Sleep-gated peer drain**：child 不 Sleep 时不 drain peer message（专注当前任务）
9. **Worker → child 仍优先**：Worker priority='user' 的 send_message 在 child 的下个 LLM turn 边界 drain；peer priority='background' 仅 Sleep 后 drain
10. **跨 family 验证**：4 family LLM peer 协作场景使用率 / 正确率 max-min spread ≤ 15pp
11. **无回归**：FEATURE_115 / FEATURE_120 既有路径全绿

### 非目标

- **不** 给 child 工具 task_stop（仅 Worker 拥有 stop 权）
- **不** 实现 child 之间的 RPC（peer message 是单向通知，不是 request/response）
- **不** 实现 priority='user' 的 child→child message（peer 是协作，不抢用户优先级）
- **不** 实现 message persistence（重启丢失）
- **不** 实现 child→child file-based mailbox（FEATURE_125 v0.8.10 Team Mode 才考虑）
- **不** 实现 cross-Worker peer（v0.8.10 Team Mode）
- **不** 给 user 暴露 peer message 的 UI（仅 agent 间用；transcript 中可见但不强调）
